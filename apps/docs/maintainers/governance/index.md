# 历史代码准入

## 为什么先进入 lab

历史实现往往混合业务文案、权限、Tailwind、私有接口和旧框架习惯。`lab-vue` 与
`lab-react` 是私有隔离区，不参与 npm 发布，允许在不承诺 API 的前提下完成审计。

## 元数据

每次迁移至少记录：

- 原仓库与相对路径；
- 固定提交和内容 blob；
- 作者/所有者确认；
- 原许可证和再许可依据；
- 原运行时依赖；
- 迁移日期、成熟度与已知风险。

## 七道门槛

| 门槛   | 要求                               |
| ------ | ---------------------------------- |
| 许可   | 有权公开，保留第三方声明           |
| 安全   | URL、HTML、存储和网络输入有边界    |
| API    | 移除业务命名，建立稳定类型         |
| 测试   | 单元、SSR、浏览器与错误路径        |
| 无障碍 | 键盘、焦点、名称、状态与 axe       |
| 性能   | 子路径不夹带其他模块，异步资源可控 |
| 文档   | 安装、API、示例、排障和许可证完整  |

任一门槛未通过都继续保留在 lab，不通过“先发布再补”的方式转嫁风险。

## EmbedPdfVue 案例

首版 PDF 组件记录了源项目提交与 blob，删除业务尾缀、Tailwind 和硬编码色值；运行时改为
Vue 专用 EmbedPDF 包，在浏览器挂载后异步导入，并补齐本地 WASM、错误阶段、资源清理、
SSR、无障碍与第三方许可说明。
